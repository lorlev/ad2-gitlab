# Configuration Reference

`auto.deploy/.env` is local server configuration for the deployment framework. It is separate from the application `.env` generated by GitLab.

Start with:

```bash
cd /datastore/web/test.example.com/auto.deploy
cp .env.example .env
chmod 600 .env
```

A complete Laravel TEST example is available at [`examples/auto-deploy.env.example`](examples/auto-deploy.env.example).

## Core settings

| Variable | Example | Purpose |
|---|---|---|
| `PROJECT` | `example-app` | Logical project name used in logs/notifications |
| `ENVIRONMENT` | `TEST` | Environment label |
| `TECH` | `laravel` | Technology module: `generic` or `laravel` |

## Framework self-update

| Variable | Example | Purpose |
|---|---|---|
| `AUTO_UPDATE` | `Y` | Check framework Git remote before a deployment |
| `AUTO_UPDATE_REMOTE` | `origin` | Git remote |
| `AUTO_UPDATE_BRANCH` | `main` | Framework branch |

When enabled, keep the `auto.deploy` directory as a valid Git checkout. Do not store local configuration in tracked files.

## Artifact source

| Variable | Example |
|---|---|
| `AWS_REGION` | `eu-central-1` |
| `S3_BUCKET` | `example-deploy-artifacts` |
| `S3_PREFIX` | `example-app/test` |

The EC2 instance role supplies AWS credentials. Do not put static AWS access keys in this file.

## Retention

```text
BUILDS_COUNT=3
```

The framework keeps the configured number of recent build directories while protecting the active release.

## Runtime identity

```text
APP_USER=www-data
APP_GROUP=www-data
```

These values control Laravel release ownership/permissions and the expected runtime identity.

## Service and health check

```text
SERVICE=example-app-test.service
HEALTH_URL=http://127.0.0.1:8001/up
HEALTH_RETRIES=10
HEALTH_DELAY=1
HEALTH_TIMEOUT=3
```

`SERVICE` must match the systemd unit used by the application.

The health check should be local and application-aware. External health is checked separately by the CI deploy job.

## PHP

```text
PHP_BIN=/usr/bin/php
```

The framework invokes the configured PHP CLI. The example documentation uses PHP 8.4; PHP 8.4+ can be used when the application and server support it.

## Laravel lifecycle switches

```text
LARAVEL_PERSIST_STORAGE=Y
LARAVEL_MIGRATE=Y
LARAVEL_CONFIG_CACHE=Y
LARAVEL_ROUTE_CACHE=N
```

- `LARAVEL_PERSIST_STORAGE=Y` keeps Laravel storage outside individual releases and links it into each build.
- `LARAVEL_MIGRATE=Y` runs migrations with `--force` before application switch.
- `LARAVEL_CONFIG_CACHE=Y` builds Laravel's configuration cache.
- `LARAVEL_ROUTE_CACHE=Y` should be enabled only when every route is compatible with route caching.

The framework does not run `db:seed` automatically.

## Notifications

Notifications are optional and server-local:

```text
NOTIF=Y
NOTIF_ENGINE=telegram
NOTIF_TOKEN=<token>
NOTIF_ID=<chat-id>
```

Keep notification credentials only in the server `.env` or another approved server-side secret source. Do not commit them or paste them into documentation/logs.

## Generic technology mode

For a non-Laravel application:

```text
TECH=generic
```

The generic module leaves application-specific hooks as no-ops while preserving release download, atomic switch, service restart, health check, retention and framework-level behavior.
